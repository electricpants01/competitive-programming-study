# 08 — Internationalization

Canonical skill: `AI/skills/astro-i18n.md`. Decision: ADR-0002.

## Layout

```
src/i18n/
  types.ts   # Translations + Slide / SlideItem / SlideStat
  en.ts
  es.ts
  utils.ts   # getLang, useTranslations, getLocalizedUrl, stripBase, isActiveLang
```

## Golden rule

Define an **explicit** `Translations` interface. Never derive types from `typeof en` with `as const` — literal types break other locales.

## Supported langs

```ts
export type Lang = 'en' | 'es';
export const SUPPORTED_LANGS: Lang[] = ['en', 'es'];
export const DEFAULT_LANG: Lang = 'en';
```

## Routing

- Pages under `src/pages/[lang]/…` export `getStaticPaths()` over `SUPPORTED_LANGS`.
- Root redirects to `/{base}/en/slides` with BASE_URL included.
- `getLocalizedUrl` / `getLang` must `stripBase()` so the base path segment is not treated as a locale.

## Passing translations to client scripts

```astro
<script is:inline define:vars={{ translations: JSON.stringify(t), currentLang: lang }}>
  window.__CP_LANG__ = currentLang;
  window.__CP_T__ = JSON.parse(translations);
</script>
```

## Feature keys

| Namespace | Feature |
|-----------|---------|
| `t.search.*` | Codeforces Problem Search |
| `t.videos.*` | Video Library |
| `t.slides.*` | Slides presentation (incl. `items: Slide[]`) |
| `t.sidebar.*` | Sidebar section/item labels |

When adding strings: update `types.ts`, `en.ts`, and `es.ts` in the same change.

## Language switcher

Top-nav EN / ES links via `getLocalizedUrl`; add `hreflang` alternates in `<head>`.

## CTA / relative hrefs

Paths in translation data that are joined as `` `${base}${lang}/${ctaHref}` `` must be relative to the lang segment (e.g. `guide`, not `../guide`).
